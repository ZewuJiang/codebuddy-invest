## 10:54 - 修复 V49 FATAL 误触发 + 自动化任务改用 minimax-m2.7-ioa 模型

- **需求**：定时任务运行报 V49 FATAL 导致上传失败，排查根因并修复；同时更换模型
- **根因分析**：
  - `run_daily.sh` 第1.5步刷新 `_meta.generatedAt` → 文件 hash 变化
  - app-sync.sh 阶段2再次调用 `run_daily.sh` → 第0.5步 validate 发现 hash 与上次上传不一致 → V49 FATAL
  - 根本原因：**双层调用导致同次运行内 hash 错位**；V49 设计目的是拦截"手工修改后忘记上传"，不应拦截 run_daily.sh 自身的正常执行
- **修复方案（3处）**：
  1. `validate.py`：新增 `--skip-v49` 参数支持，跳过时 SKIP 而非 FAIL（v6.3）
  2. `run_daily.sh`：调用 validate 时固定传 `--skip-v49`（run_daily 本身会完成上传，V49 无意义）
  3. `app-sync.sh`：模型 `hy3-preview-ioa` → `minimax-m2.7-ioa`
- **产出**：修改 3 个文件，V49 的有效检测场景（手工改文件后忘记上传）不受影响，下次 run_daily.sh 执行时仍会检测
